# Redesign Protocol

Read when the work is a redesign or refresh of something that already exists,
rather than new construction.

## 1. Detect the mode first

| Mode | Signal | Dial effect |
|---|---|---|
| `Preserve` | brand is established, user wants modernisation not reinvention | match existing variance/density, motion +1 |
| `Overhaul` | user is explicitly unhappy with the current identity | variance +2, motion +2, density matched to surface |

If the user has not said which, ask — this is the one question worth spending.

## 2. Audit before touching anything

Inventory the existing artifact and write down what you found. Do not start
editing from an impression.

- Brand assets present: logo, wordmark, color values, typefaces, photography
- Current type scale, spacing scale, radius scale, shadow usage
- Component inventory and which ones are load-bearing
- Content structure: sections, their jobs, their order
- What actually works — name at least two things worth keeping
- What is broken: contrast failures, layout breaks, missing states, dead links
- Constraints: framework, CMS, existing tokens, a11y obligations

The audit is the input to the Design Read. Existing brand assets are starting
material, not optional suggestions.

## 3. Preservation rules

Never change these silently — surface them and ask:

- Brand name, logo, wordmark
- Established brand colors
- Legal, compliance, or regulatory copy
- URL structure and navigation labels users have learned
- Anything the user explicitly praised

## 4. Modernisation levers, in priority order

Apply top-down and stop when the brief is satisfied. Most "it looks dated"
complaints are solved by the first three.

1. Type scale and pairing — the highest-leverage change
2. Spacing rhythm and whitespace — usually the real problem
3. Contrast and color discipline — one accent, one neutral temperature
4. Surface treatment — remove card chrome, tint shadows, lock radius
5. Layout structure — break symmetry, vary section families
6. Imagery — replace stock/abstract with real assets
7. Motion — add last, and only where it communicates something

## 5. Targeted evolution vs full redesign

Full redesign only when the audit shows the structure itself fails the job:
wrong information architecture, wrong surface classification (marketing patterns
on an app), or an identity the user has rejected. Otherwise, targeted evolution
against levers 1-4 delivers most of the perceived improvement at a fraction of
the risk.

## 6. Mock presentation for redesigns

Layer 1 mocks in redesign mode always include a **before** capture of the
current state alongside the candidate directions, so the comparison is real and
not remembered.
