# Installed Wayne skills

- `wayne-checkpoint`: Save and resume working state within the project, and act as the handoff conductor between Wayne pipeline stages. Captures git state, decision log progress, plan status, and remaining work so you can pick up exactly where you left off across sessions. Also emits a standardized "handoff packet" (snapshot + next agent + self-contained next prompt + optional goal) at the end of each pipeline stage to standardize the transition to the next stage — without ever advancing it. Stored under <state>/checkpoints/ (per-project under ~/.wayne, shared by all worktrees, never in the repo). Use when asked to "checkpoint", "save progress", "where was I", "resume", "pick up where I left off", or "hand off"; also auto-called by other Wayne pipeline skills as their final step to produce a handoff packet.
- `wayne-code-review`: Dual-voice code review combining structured analysis with adversarial cross-model challenge. Dispatches subagent + Codex for independent opinions, then synthesizes. Use before merging, after completing features, or when stuck. Trigger on "review my code", "code review", "check my diff", "review before merge".
- `wayne-codebase-report`: Deep-read an unfamiliar codebase and produce an engineering report whose every citation is mechanically verified. Use for "study this repo", "read dsh and write a report", "what can we learn from project X", "深读这个仓库", "写份调研报告". Not for diagnosing a failure (wayne-triage) or reviewing your own diff (wayne-code-review).
- `wayne-compress`: Retro after a task. Reads the session logs, finds where the agent lost time or erred, and turns each finding into one change to the environment (a check, a pointer, an access grant, a deleted rule), then prunes the task's context.md into the project. Writes no lesson docs. Use for "retro", "compress", "复盘", "收尾", "that worked", "/wayne-compress"; next step after wayne-ship.
- `wayne-context-audit`: See which skills you actually use, to decide what to prune. Reads the PreToolUse skill-usage log (~/.claude/skill-usage.jsonl) and reports per-skill invocation counts, last-used / days-idle, and installed-but-never-used prune candidates. For the static snapshot of what's loaded right now (per-item token cost of skills, agents, MCP, memory), just run the built-in `/context all` — this skill does NOT re-derive that. Use when asked to "audit skills", "which skills do I use", "is this skill used", "clean up my skills", or "what can I remove".
- `wayne-context-init`: Starts a task's context model before work begins — what proves it works, what the agent can reach, what it must know, which lines it must not cross — in the run's context.md, seeded from the project file. Use for "init context", "初始化 context", "context 模型", "/wayne-context-init"; run by mind-explode, plan, and delegate when a task has none. Not for pruning context (wayne-compress).
- `wayne-cybernetics`: Apply Qian Xuesen's engineering cybernetics lens to system / architecture / process / debug / knowledge problems. Distills 8 principles (system identification, observability, controllability, single SoT, hierarchical control, signal-to-noise, minimum control effort, feedback stability) and walks them as a diagnostic checklist. Use when asked to "用控制论分析", "apply cybernetics", "system design audit", "architecture review", "find drift sources", "diagnose this system", "why is this control plane unstable", "find redundancy in this design".
- `wayne-distill`: Distill reusable PATTERNS out of past sessions across ALL FOUR agents — Claude Code (~/.claude/projects), Codex CLI (~/.codex/sessions), pi (~/.pi/agent/sessions) and omp (~/.omp/agent/sessions). Semantic clustering (multilingual embedding + Leiden) groups prompts by MEANING across 中文/English, then an LLM analyst fans over the communities to induce patterns: both reusable procedures you re-run by hand AND recurring agent mistakes you keep correcting. Each surviving pattern gets a fate — a new skill, an anti-pattern attached to an existing skill, or a redirect to compress/memory. Writing the actual SKILL.md is wayne-skill-forge's job — distill writes the pattern, forge writes the skill. Distinct from wayne-compress (which retros ONE finished task into environment changes); wayne-distill mines the WHOLE history for missing patterns. Triggers: "/wayne-distill", "蒸馏一个新 skill", "从历史里找 skill", "distill a skill from my sessions", "what should be a skill", "agent 老犯的错做成 skill", "distill agent failure patterns".
- `wayne-explain`: Re-explain in plain Chinese only on request ("我不懂", "说人话", "这fix了个啥玩意", "你在干啥", "咋回事", "plain chinese", or an ELI level / audience). Not for prose polishing or a TL;DR.
- `wayne-fix-review`: Verify existing PR comments with contextual evidence, explain impact, likelihood and recovery, wait for the user's fix selection, then plan repairs and execute through wayne-work. Use for 'address review comments', 'fix the findings', or '先验证再修 PR 评论'. Consumes posted feedback; not a new code review or PR-status lookup.
- `wayne-frontend-design`: Wayne UI/UX design. Classifies the surface (marketing / application / operations / component), sets variance-motion-density dials, then presents 2-3 rendered visual mocks and iterates until the user picks one; no full build before a direction is approved. Defers to existing design systems. Chinese to user, English in files. Use for landing pages, web apps, dashboards, components, prototypes, redesigns, slides. Trigger on "design this", "build UI", "make a landing page", "redesign this", "frontend work", "wayne design".
- `wayne-goal-prompt`: Turns vague or plan-backed intent into a six-section goal for an autonomous run, asks one evidence-closing question when needed, preserves exact verification and real-path proof, gates on user confirmation plus cwd, then dispatches through the bundled headless Codex adapter with fail-loud startup and same-thread resume. Use for goal prompt, sharpen this goal, 写个 goal, 帮我把 goal 补好, or /goal 怎么写.
- `wayne-inbox`: Wayne's chief of staff: the omp session that receives inbox cards (PR events, agent session results, Teams) from ~/.wayne/inbox, routes each to the right owner, delegates real work to agent sessions, verifies results and reports. Use for: inbox, what's waiting for me, watch a PR or an agent session, stop watching, resume watches after a restart, close an inbox item, edit inbox rules.
- `wayne-manner`: Manage and query Wayne's personal knowledge base at the path configured by `WAYNE_KB_DIR`. Use when saving lessons, recalling prior decisions, searching the KB, updating existing notes, or ingesting new findings into the vault. Trigger on "save this to KB", "search KB", "what do we know about X", "recall X", or "update KB".
- `wayne-mind-explode`: Converges a feature, system, or architecture idea through repository-grounded questioning into an approved decision log, test matrix, and design spec, then runs three independent design reviews and hands off to wayne-plan. Use for “brainstorm”, “mind explode”, “let's design”, “grill me”, or equivalent Chinese design requests; never use it to implement or write the implementation plan.
- `wayne-neat`: OCD-level reconciliation of project docs (CLAUDE.md/AGENTS.md, README, docs/) and agent memory against actual code state. Three input sources: this conversation, git log since last sync, and code comments in modified files — catches drift the chat didn't surface. Subagent fan-out in two batches (master read + verification). MUST trigger on: "neat", "tidy up docs", "sync docs", "update memory", "/neat", "/sync", "整理一下", "整理文档", "同步一下", "更新记忆", "梳理一下", "收尾", "这个阶段做完了", or any phrase suggesting a milestone where knowledge needs reconciliation. Also trigger when the user reports stale docs, conflicting memory, or wants a clean handoff. Bare "整理"/"tidy" with prior dev context counts — do not under-trigger.
- `wayne-plan`: Create a durable implementation plan from an approved decision log, spec, test matrix, or converged request. Use for “plan this,” “create a plan,” “implementation plan,” “how do we build this,” and equivalent Chinese requests; do not use for brainstorming, test-matrix design, implementation, execution, commits, or shipping.
- `wayne-rescue-boot`: Rescue a machine that won't boot — kernel panic, "VFS: unable to mount root", drops to (initramfs) BusyBox, GRUB missing/broken — when your only access is IPMI/BMC (Supermicro etc.) or a physical console. Get into a Live rescue env, PROVE whether the disk is actually dead vs a software boot fault (the two look identical from the panic screen), then chroot-fix the real cause: missing initramfs, dangling initrd symlink, root=/dev/sdX device-name drift, bad fstab. Verify from the real disk, not "looks like it booted". Diagnose-then-fix on the actual box; NOT a static log triage, NOT a data probe. Triggers: "rescue boot", "won't boot", "kernel panic", "VFS unable to mount root", "stuck in initramfs", "dropped to busybox", "boot repair", "mount rescue ISO via IPMI", "fix grub / initramfs", "机器起不来", "内核 panic", "进不去系统", "救援启动", "挂不了 root", "boot 不了了", "ipmi 挂 iso 救援", "重建 initramfs". Do not under-trigger — any "the machine panics / won't come up and I only have IPMI" is this skill.
- `wayne-ship`: Commit and ship changes following Wayne commit conventions. 1 commit = 1 feature. Jira ticket prefix, signed-off, [why]/[how] format. Gates on the wayne-code-review-flow PASS verdict for the range being pushed. Use when asked to "commit", "ship", "push", "create PR", or "land this".
- `wayne-simplify`: Post-write refinement over a settled, already-green diff: finds duplication, needless complexity, and speculative abstraction in the code just written, applies the edits, then re-runs the same verification to prove behavior unchanged. Use for "simplify this", "简化一下", "太复杂了", "clean up what we just wrote", "over-engineered", "reduce this diff". Never changes behavior or drops approved scope.
- `wayne-skill-forge`: Creates or revises lean Wayne-style skills from approved intent or wayne-distill evidence. Chooses procedure, lens, or router; keeps loader metadata valid; and A/B tests real behavior. Use for "/wayne-skill-forge", "建一个 skill", "把这个做成 skill", "写个 skill", "create a skill", "scaffold a skill", or "slim this skill".
- `wayne-skill-optimize`: Runs a validation-gated optimization loop on one existing skill using exact failure cases, frozen control/candidate comparisons, and held-out regressions. Use for “optimize this skill”, “improve this skill from failures”, “evolve this skill”, “skill A/B”, or systematic Wayne-skill slimming; use wayne-skill-forge directly to create a new skill from approved intent.
- `wayne-test-design`: Designs a durable two-layer test matrix from an approved spec, bug, plan, or converged request: provisional U-SEED cases for wayne-plan, and an E2E contract written as executable Given/When/Then scenarios for wayne-verify. Asks the user for the runtime environment recipe before approval, isolates provider/proof axes, rejects capability claims without native evidence, and avoids impossible test dimensions. Use for test design, test matrix, given when then, what tests do we need, 测试设计, or 测试矩阵; never writes or runs tests.
- `wayne-triage`: Diagnoses a supplied failure, incident, log, test failure, issue, PR, or Jira item just far enough to establish evidence-backed attribution and route one next Wayne stage. Use for “triage”, “root cause”, “why is this failing”, “diagnose this”, “flaky test”, “production incident”, “triage
- `wayne-verify`: Executes a carried E2E Verification Contract through the real process, data, entrypoint, and user path; captures fresh observable evidence; mutates only E2E Status and the project verification recipe; and gates shipping. Use for verify, e2e, run the feature, does it actually work, runtime verification, or /wayne-verify; never substitute unit tests or static review.
- `wayne-visual-synthesis`: Builds exhaustive Visual Element Ledgers from images before deriving descriptions, OCR transcripts, or semantic equivalents. Use for image/screenshot reading, visible-element inventory, OCR, charts, tables, diagrams, documents, targetable visual structure, or explicit image comparison. Compare mode runs both pixel/channel and ledger-level diffs and separates render noise from real semantic change.
- `wayne-work`: Executes an approved Wayne plan unit by unit: validates inputs and scope, establishes requested RED evidence, implements and verifies each unit, simplifies each finished wave with wayne-simplify before auditing it, commits each audited unit, checks owned U rows while preserving E rows, proves the full diff, and hands off to wayne-code-review. Use for ‘build this’, ‘implement/execute the plan’, ‘start working’, ‘let's build’, or equivalent Chinese implementation requests with a durable plan.
- `delegate-agent-session`: Delegate a coding/research job to a new omp session in tern, herdr or tmux (local or <remote-host>), register it with wayne-inbox, follow up, verify its RESULT; for 开个 session, delegate, send to <remote-host>
